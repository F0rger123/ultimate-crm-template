# Master Requirements

> **The single registry of everything the owner wants.** Most important file in the project.
> Rules: `AGENTS.md` §1–2 and `docs/PROCESS.md`. Short version:
> - Every item has a permanent ID (`REQ-001`, `REQ-002`, …). Never renumber, reuse, or delete.
> - "Implemented" ≠ "Verified". Record the evidence level actually reached.
> - Changed requirement → edit it **and** add a dated History line. Big change → `Superseded by REQ-xxx`.
> - Owner reports it's still broken → reopen this item (or its linked bug), don't create a duplicate.
> - Agent ideas go to `IDEAS.md` first. Only the owner approves.

**Types:** FEATURE · BUG · IMPROVEMENT · DESIGN · BRANDING · INTEGRATION · AUTOMATION · WORKFLOW · DATA · SECURITY · PERFORMANCE · CONTENT · REPORTING · PORTAL · MOBILE
**Statuses:** Needs Clarification · Proposed · Approved · Planned · In Progress · Partially Implemented · Implemented · Needs Testing · Blocked · Resolved · Verified · Rejected · Deferred · Superseded
**Priority:** Critical · High · Medium · Low
**Evidence:** — · CODE WRITTEN · LOCAL TEST PASSED · INTEGRATION TEST PASSED · USER TESTED · PRODUCTION VERIFIED
